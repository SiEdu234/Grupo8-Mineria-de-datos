def parse_bert_vector(value, width=32):
    result = np.full(width, np.nan, dtype=np.float32)
    if pd.isna(value):
        return result
    numbers = re.findall(r'[-+]?(?:\d*\.\d+|\d+\.?)(?:[eE][-+]?\d+)?', str(value))
    try:
        parsed = np.asarray([float(x) for x in numbers[:width]], dtype=np.float32)
    except ValueError:
        return result
    result[:len(parsed)] = parsed
    return result

3. Reglas de los Arboles de Decision (Matematicas del Modelo)

Fundamento teorico y algebraico de como decide Random Forest

Como explicar la toma de decisiones de un arbol: "Profesora: Cada arbol de decision realiza divisiones binarias recursivas del tipo $x_j \le c$. En cada nodo interno, el algoritmo evalua todas las variables candidatas y busca el punto de corte $c$ que maximice la reduccion de impureza Gini ($\Delta Gini$). Los arboles no generan formulas algebraicas lineales continuas, sino un conjunto jerarquico de reglas condicionales Si-Entonces (If-Else) sobre las caracteristicas de interaccion del alumno."
1

Regla de Bifurcacion Binaria (Condicion de Corte)

En cada nodo $t$, el arbol elige una variable $x_j$ y un umbral $c$:

$$\text{Si } x_j \le c \implies \text{Hijo Izquierdo } t_L; \quad \text{Si } x_j > c \implies \text{Hijo Derecho } t_R$$
2

Criterio de Impureza de Gini

Mide el grado de mezcla de clases en el nodo ($k \in \{0, 1\}$). Si el nodo es 100% puro (todos fallaron o todos acertaron), $Gini = 0$:

$$Gini(t) = 1 - \sum_{k=0}^1 p_k^2 = 1 - (p_0^2 + p_1^2)$$

• Nodo completamente puro: $p_0=1, p_1=0 \implies Gini = 1 - (1^2 + 0^2) = 0.0$
• Nodo en maxima incertidumbre (50/50): $p_0=0.5, p_1=0.5 \implies Gini = 1 - (0.25 + 0.25) = 0.5$

3

Ganancia de Informacion / Reduccion de Impureza ($\Delta Gini$)

El algoritmo elige el corte $(j, c)$ que produzca la mayor caida de impureza ponderada por el tamano de los hijos:

$$\Delta Gini(s, t) = Gini(t) - \left[ \frac{N_L}{N_t} Gini(t_L) + \frac{N_R}{N_t} Gini(t_R) \right]$$

¿Por que es Invariante a Escala (Sin StandardScaler)?

A diferencia de una regresion logistica o red neuronal (donde las variables grandes dominan los pesos $w$), un arbol evalua cada variable por separado. Como la particion $x_j \le c$ depende unicamente del orden relativo de los datos, aplicar estandarizacion matematica desplaza la constante $c$ pero produce exactamente el mismo split.

¿Como Maneja el Arbol el Valor Imputado -1?

Como todas las variables reales de conteo o ratios son $\ge 0$, el arbol puede colocar un corte simple como $x_j \le -0.5$. Todos los casos ausentes caen juntos en el hijo izquierdo, aprendiendo una regla propia de riesgo para alumnos sin datos sin distorsionar los datos positivos.

Principio de Ensamble de Leo Breiman (Bagging + Random Subspace)

Un solo arbol de decision tiene alta varianza (tiende a sobreajustar). Random Forest resuelve esto mediante dos reglas clave:
1. Bootstrap Aggregating: Cada arbol se entrena con un remuestreo aleatorio con reemplazo de tamano $N$ (~63.2% de datos unicos).
2. Subespacio Aleatorio: En cada nodo solo se prueban $m = \lfloor \sqrt{722} \rfloor = 27$ variables aleatorias para obligar a los arboles a explorar senales distintas.
3. Voto de Mayoría / Promedio: La probabilidad final es el promedio de las hojas terminales de los 600 arboles:

$$P(Y = k \mid x) = \frac{1}{B} \sum_{b=1}^{B} P_b(Y = k \mid x), \quad B = 600$$

¿Por que no entrenar con el 100% de unit_test_scores.csv?

Porque en Machine Learning es una regla inviolable no evaluar un modelo con los mismos datos con los que aprendio. Si entrenaramos con el archivo maestro de ~576,000 registros, el modelo simplemente memorizaria las notas de los alumnos (Sobreajuste / Overfitting). Los organizadores del concurso ocultaron ~124,000 registros de prueba para medir si el algoritmo verdaderamente generaliza ante estudiantes nuevos.

5. Los 8 Hiperparametros Configurados en Scikit-Learn

Ubicacion: Cuaderno ASSISTments_RF_Colab_ES.ipynb • Celda 4 • Lineas 22-31

ASSISTments_RF_Colab_ES.ipynb Celda 4 • Constructor Real 
rf = RandomForestClassifier(
    n_estimators=N_ESTIMATORS,  # 600 arboles (estabilidad en probabilidades, vs 100 por defecto)
    max_depth=19,            # Poda a profundidad 19 (evita sobreajuste, vs None por defecto)
    min_samples_split=10,    # Minimo 10 muestras para dividir un nodo (vs 2 por defecto)
    min_samples_leaf=2,      # Minimo 2 muestras por hoja terminal (vs 1 por defecto)
    max_features='sqrt',     # Breiman: floor(sqrt(722)) = 27 variables aleatorias por nodo
    bootstrap=True,          # Remuestreo con reemplazo para cada arbol (~63.2% datos)
    random_state=SEED,       # Semilla 42 (reproducibilidad cientifica exacta)
    n_jobs=-1                # Paralelizacion en todos los nucleos CPU disponibles
)
Hiperparametro Valor Usado Defecto Sklearn Funcion Principal ¿Que pasa si se AUMENTA? ¿Que pasa si se DISMINUYE?
n_estimators 600 100 Numero de arboles independientes construidos en el ensamble. Reduce varianza hacia una asintota (Teorema de Breiman: no sobreajusta); eleva tiempo y consumo de RAM. Entrenamiento veloz, pero mayor varianza e inestabilidad en las probabilidades estimadas.
max_depth 19 None (infinita) Limite maximo de profundidad desde la raiz hasta las hojas terminales (poda). Sobreajuste (Overfitting): El arbol crece hasta hojas puras memorizando ruido; train=100%, test cae. Subajuste (Underfitting): Arboles demasiado cortos incapaces de aprender interacciones no lineales complejas.
min_samples_split 10 2 Numero minimo de observaciones en un nodo para intentar una nueva division. Mayor regularizacion; impide bifurcaciones provocadas por grupos pequenos aislados. Permite dividir nodos con pocas observaciones (hasta 2), favoreciendo sobreajuste en hojas.
min_samples_leaf 2 1 Numero minimo de datos exigidos en cada hoja terminal. Suaviza fronteras de decision garantizando soporte estadistico en cada hoja. Permite hojas de 1 solo dato, memorizando observaciones atipicas (outliers).
max_features 'sqrt' (27) 'sqrt' Variables candidatas evaluadas al buscar el mejor corte: $$m = \lfloor \sqrt{722} \rfloor = 27$$ Arboles mas parecidos entre si; aumenta la correlacion inter-arbol y reduce la ganancia de Bagging. Mayor diversidad entre arboles, pero cada arbol individual es ligeramente mas debil.
bootstrap True True Muestreo con reemplazo de tamano $N$ para cada arbol (~63.2% datos unicos). (Booleano): Garantiza diversidad estructural, base fundamental del algoritmo Random Forest. Si fuera False, todos los arboles tendrian datos identicos, destruyendo el ensamble.
random_state 42 None Semilla pseudoaleatoria fija para bootstrap y seleccion de variables. Fija el estado de aleatoriedad; garantiza que cualquier persona obtenga exactamente los mismos resultados. Si es None, cada corrida genera arboles y metricas con ligeras variaciones estocasticas.
n_jobs -1 None (1 core) Cantidad de nucleos CPU para paralelizar la construccion de los 600 arboles. Aprovecha el 100% de vCPUs en paralelo; acelera el tiempo sin alterar los calculos matematicos. Si se pone 1, ejecuta en un solo hilo secuencial tardando de 4 a 8 veces mas tiempo sin beneficio.

6. Preguntas Frecuentes y Respuestas Verbales "Para Decir en Vivo"

Haz clic en cada tarjeta para repasar las preguntas que la profesora acostumbra hacer durante la defensa

1. ¿Por que dicen que preprocesaron y codificaron, pero aclaran que no normalizaron matematicamente? +

Respuesta verbal exacta:

"Profesora: Porque convertir palabras a 1 y 0 es tecnicamente Codificacion (One-Hot Encoding con pd.get_dummies). La normalizacion o estandarizacion matematica (como StandardScaler) ajusta escalas numericas mediante medias y desviaciones estandar. En nuestro modelo no aplicamos StandardScaler porque Random Forest es un ensamble de arboles de decision que evalua cortes individuales por impureza Gini, siendo completamente invariante a transformaciones monotonicas de escala."

2. Si les pido en la laptop cambiar max_depth a 45 o None y re-ejecutar, ¿que pasara con las metricas y por que? +

Respuesta verbal exacta:

"Profesora: Si aumentamos max_depth a 45 o None, eliminamos el freno de poda. Los arboles creceran hasta que cada hoja sea pura, memorizando el ruido particular de los datos de entrenamiento. En entrenamiento el Accuracy llegara al 99-100%, pero en la particion de evaluacion el error crecera y el AUC caera debido al fenomeno de Sobreajuste (Overfitting). Con max_depth=19 controlamos la complejidad estructural de cada estimador."

3. ¿Por que tener 600 arboles no produce sobreajuste segun la teoria? +

Respuesta verbal exacta:

"Profesora: Segun el Teorema de Leo Breiman (fundador de Random Forest), aumentar el numero de arboles ($n\_estimators$) no sobreajusta porque el error de generalizacion converge asintoticamente a un limite finito. Lo unico que ocurre al subir a 1,500 arboles es que el tiempo de computo se alarga y se consume mas memoria RAM en Colab sin aportar ganancia apreciable en el AUC."

4. ¿Por que imputaron con 0 en acciones y con -1 en variables generales? +

Respuesta verbal exacta:

"Profesora: Porque el significado pedagogico es completamente distinto. En los logs de acciones, si un alumno no tiene registros de pedir pistas significa que realizo 0 peticiones (ausencia de evento = 0). En cambio, en variables numericas generales de diseno, un dato ausente representa falta de informacion; al imputarlo con -1, los arboles de decision pueden generar una regla de corte natural como $x_j \le -0.5$, aislando a los alumnos sin dato en una rama propia sin contaminar la media de los datos reales."

5. ¿Cual es la diferencia entre la salida continua y discreta del modelo en el codigo? +

Respuesta verbal exacta:

"Profesora: La salida discreta la genera rf.predict(X_test), entregando un 0 o un 1 segun el umbral estandar de 0.5. La salida continua la genera rf.predict_proba(X_test), entregando la probabilidad exacta calculada como el porcentaje de votos entre los 600 arboles. Esta probabilidad continua es la que permite construir la Curva ROC (AUC = 0.753) y activar alertas docentes tempranas personalizadas en un dashboard cuando $P(score=0) > 0.40$."
